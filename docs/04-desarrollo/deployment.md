# Despliegue

PENDIENTE: se define en la FASE 10 con la decisión D7 (hosting y respaldos).

Lo que ya se sabe que hace falta:

| Componente | Detalle |
|---|---|
| Worker de colas | `php artisan queue:work` con las colas `sifen`, `whatsapp` y `default` |
| Scheduler | `php artisan schedule:run` cada minuto (recordatorios, avisos de vencimiento) |
| Archivos privados | Fotos, adjuntos, PDF, XML de SIFEN y el certificado `.p12`, fuera de `public` |
| Zona horaria | `APP_TIMEZONE=America/Asuncion` |
| Zona de la sesión de MySQL | `DB_TIMEZONE=-03:00` en el `.env`, sin dejarla vacía (una vacía toma `-03:00`, pero otro valor inválido rompe toda conexión). Fija cómo guarda MySQL las columnas `timestamp`, sin depender de la zona del servidor; un desplazamiento fijo porque las zonas con nombre de MySQL no siempre están cargadas (deuda 16, R-049). Comprobar en el servidor que `SELECT @@session.time_zone` desde la aplicación dé `-03:00` (el detalle, en [`setup.md`](setup.md#zona-de-la-sesión-de-mysql)) |
| PHP: base de zonas 2025a o posterior | Paraguay es UTC-3 todo el año desde el 15/10/2024; con una base de zonas anterior, PHP sigue usando `-04:00` de marzo a octubre y las fechas con hora quedan una hora corridas. Actualizar PHP o instalar la extensión `timezonedb`; comprobar en el servidor que `tests/Unit/AsuncionTimezoneTest` pase (el detalle, en [`setup.md`](setup.md#zona-horaria-de-paraguay-base-de-zonas-de-php)) |
| PHP: `zend.exception_ignore_args=On` | Obligatorio en producción (es el valor de `php.ini-production`). Con `Off`, las trazas del log muestran los argumentos de cada llamada. La contraseña del login ya va con `#[\SensitiveParameter]` y los errores de negocio no se reportan, pero esta opción cubre cualquier otro dato que llegue a una traza |
| Proxies de confianza | `TRUSTED_PROXIES` (`config/trustedproxy.php`), vacía por defecto: no se confía en ningún proxy y se ignora `X-Forwarded-For`. Detrás de un balanceador o proxy inverso, poner su IP o rango (`10.0.0.1` o `10.0.0.0/8,192.168.1.10`); `*` solo si la aplicación no es accesible sin pasar por el proxy. Sin esto, detrás de un proxy todos los usuarios comparten su IP: el límite de intentos del login queda solo por usuario (5 fallidos bloquean a esa persona en todas partes) y la auditoría registra la IP del proxy |
| Caché: Redis | `CACHE_STORE=redis`. El límite de intentos del login usa la caché, y con `database` el contador no es atómico: en una ráfaga simultánea pasan de 0 a 4 intentos de más (deuda 6, [`03-plan-desarrollo/deuda-tecnica.md`](../03-plan-desarrollo/deuda-tecnica.md)). Redis incrementa de forma atómica; verificar al desplegar que 20 logins fallidos simultáneos dejen pasar exactamente 5 (si no, envolver el `hit` en `Cache::lock`) |
| Salida a internet: Have I Been Pwned | La regla de contraseñas (R-009) consulta `https://api.pwnedpasswords.com` al crear un usuario (`clinic:create`, el `DemoSeeder` y, desde la FASE 2, el ABM de usuarios). Solo viajan los 5 primeros caracteres del SHA-1. Espera como mucho 3 segundos: sin respuesta, la contraseña se acepta, queda un aviso en el log con el código de error de cURL o el estado HTTP, sin traza ni contraseña, y la consola lo avisa (`PwnedPasswordsVerifier`, R-010 y R-011) |
| PHP: `curl.cainfo` y `openssl.cafile` | Comprobar en producción que apunten a un `cacert.pem` que exista. Con una ruta inválida **toda** consulta HTTPS de PHP falla (cURL error 77): Have I Been Pwned nunca responde y la regla de contraseñas acepta cualquiera, también las filtradas (pasó en el entorno de desarrollo, R-011). Verificar con `php -r "echo ini_get('curl.cainfo'), PHP_EOL;"` que el archivo exista y que `php artisan tinker --execute="var_dump(App\Support\UserPassword::error('Password123!'));"` devuelva el mensaje de contraseña filtrada (no `NULL`), sin el aviso de Have I Been Pwned en el log |
| Log | `storage/logs` no debe tener contraseñas ni tokens. Los errores de negocio (`AppException`) no se escriben; `ClinicContextMissingException` sí, porque es un bug |
